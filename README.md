# Nexaire Tech — AI Sales Trainer Demo

Рабочее web-демо AI-тренажера продаж для проверки гипотезы на B2B-рынке. Nexaire Tech здесь используется как направление внутри Nexaire, не как название продукта.

## Что уже реализовано

- Главная страница с B2B-позиционированием.
- Выбор из 5 сценариев тренировки.
- Чат, где пользователь играет менеджера Nexaire Auto, а AI играет клиента.
- Начальное сообщение AI-клиента.
- Завершение диалога вручную.
- Предупреждение при слишком раннем завершении.
- Финальная AI-оценка по критериям продаж.
- Структурированный JSON для оценки.
- Форма заявки с обязательным согласием на политику конфиденциальности.
- Логирование заявок в `data/leads.jsonl`.
- Опциональная отправка заявок на email `info@nexaire.ru` через SMTP.
- Опциональная отправка заявок в Telegram.
- Адаптивный интерфейс.
- Loading/error-состояния.
- Rule-based mock-режим для показа демо без API-ключа: клиент реагирует на смысл ответа менеджера, а оценка считается локально по статистике диалога.

## Запуск локально

### 1. Установить зависимости

```bash
npm install
```

### 2. Создать `.env.local`

```bash
cp .env.example .env.local
```

### 3. Выбрать режим

Для демо без API-ключа оставьте mock-режим:

```env
AI_PROVIDER=mock
USE_MOCK_AI=true
```

В этом режиме клиент и финальная оценка работают без внешних AI-сервисов.

Для режима с GigaChat:

```env
AI_PROVIDER=gigachat
USE_MOCK_AI=false
GIGACHAT_AUTH_KEY=ваш_ключ_авторизации
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
```

`GIGACHAT_AUTH_KEY` можно вставить как сырой base64-ключ или как полное значение с префиксом `Basic ...`.

Для режима с OpenAI:

```env
AI_PROVIDER=openai
USE_MOCK_AI=false
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-5.6
```

Если `AI_PROVIDER` не задан, приложение выберет mock, GigaChat или OpenAI по доступным ключам. Для стабильного показа лучше задавать `AI_PROVIDER` явно.

### 4. Запустить dev-сервер

```bash
npm run dev
```

### 5. Открыть в браузере

```txt
http://localhost:3000
```

## Rule-based mock-логика

В mock-режиме больше нет случайных универсальных реплик. После каждого ответа менеджера приложение:

1. анализирует текст менеджера: вопросы, конкретику, цену, бюджет, документы, риски, проверку, расчет, следующий шаг, давление и опасные обещания;
2. обновляет состояние клиента: доверие, сомнение, интерес, готовность, этап диалога и номер хода;
3. выбирает реплику из базы конкретного сценария;
4. при завершении считает оценку без OpenAI API.

Критичные реакции клиента:

- короткий/общий ответ → клиент просит конкретику;
- давление → клиент закрывается;
- обещания “точно пройдет”/“без рисков” → клиент настораживается;
- вопросы о бюджете/потребности → клиент раскрывает вводные;
- документы/риски/расчет → клиент задает следующий логичный вопрос;
- понятный следующий шаг при достаточном доверии → клиент соглашается.

## Email-уведомления о заявках

Форма заявки отправляет данные в `/api/lead`, сохраняет их в `data/leads.jsonl` и при наличии SMTP-настроек отправляет уведомление на почту. Получатель по умолчанию:

```env
LEAD_EMAIL_TO=info@nexaire.ru
```

Для реальной отправки писем нужно добавить SMTP-доступ в `.env.local`:

```env
LEAD_EMAIL_TO=info@nexaire.ru
LEAD_EMAIL_FROM=info@nexaire.ru
SMTP_HOST=smtp.example.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=info@nexaire.ru
SMTP_PASS=пароль_или_app_password
```

Если SMTP не настроен, заявка не потеряется: она сохранится локально в `data/leads.jsonl`, а в консоли появится предупреждение.

Перед кнопкой отправки добавлен обязательный чекбокс согласия:

```txt
Оставляя заявку, вы соглашаетесь с политикой конфиденциальности и обработки персональных данных.
```

Ссылка ведет на `https://nexaire.ru/privacy.html`.

## GigaChat: ошибка `SELF_SIGNED_CERT_IN_CHAIN`

Если в консоли появляется ошибка:

```txt
Error: self-signed certificate in certificate chain
code: 'SELF_SIGNED_CERT_IN_CHAIN'
```

это не ошибка ключа. Это значит, что Node.js на вашей машине не доверяет цепочке сертификатов, которую использует GigaChat.

### Быстрый вариант для локального теста

В `.env.local` можно временно включить:

```env
AI_PROVIDER=gigachat
USE_MOCK_AI=false
GIGACHAT_DISABLE_TLS_REJECT=true
```

После изменения `.env.local` остановите dev-сервер и запустите заново:

```bash
npm run dev
```

Важно: `GIGACHAT_DISABLE_TLS_REJECT=true` отключает проверку TLS-сертификата. Это допустимо только для локальной проверки демо. Для production так не делать.

### Правильный вариант

Установите российские доверенные сертификаты Минцифры по инструкции GigaChat и запустите Node с дополнительным CA bundle через `NODE_EXTRA_CA_CERTS`.

Для PowerShell пример выглядит так:

```powershell
$env:NODE_EXTRA_CA_CERTS="C:\certs\russian-ca-bundle.pem"
npm run dev
```

`NODE_EXTRA_CA_CERTS` нужно задавать до запуска Node.js. Если добавить его только в `.env.local`, Node может не успеть применить сертификат при старте процесса.

## Обновление: fallback для примера улучшенного ответа

Исправлена ситуация, когда GigaChat возвращал пустое поле `betterResponseExample`, и на странице результата был только заголовок без текста.

Что изменено:

- промпт оценщика теперь прямо требует непустой `betterResponseExample`;
- серверный парсер больше не принимает пустую строку как валидный пример;
- если модель все равно вернула пустое поле, сервер подставляет сценарный fallback-пример по текущему сценарию;
- интерфейс результата дополнительно страхуется и показывает fallback, если поле по какой-то причине пустое на клиенте;
